# Analysis Report — Shree Ram Transport (SRT) Dashboard

**Source file:** `srt-dashboard(6) (1).html`
**Size:** 3,075,539 bytes / 10,648 lines — a single monolithic HTML file containing the entire application (markup, ~30 `<style>` blocks, ~17 `<script>` blocks, 9 embedded base64 images, and one full secondary HTML application embedded as a JS string).

This is a **100% client-side, browser-only prototype**. There is no server, no API, no real database — every "module" is a JavaScript object/array persisted to `localStorage`. The goal of this project is to turn it into a real FastAPI + MySQL + JWT multi-user application while keeping the **exact same visual output and behavior**.

## 1. Document Structure

Three top-level `<div class="page">` sections, shown/hidden by JS (`.page.active`): `#pg-home` (public marketing site), `#pg-login` (split-screen login page, `#srt-login-form`), and `#pg-dash` (the dashboard shell with one `<div class="cp">` per module).

**Content pages (`#cp-*`):** `cp-home` (KPIs/charts), `cp-taxinvoice` (embedded secondary HTML app), `cp-inv`, `cp-pay`, `cp-cp`, `cp-rp` (financial record tables), `cp-gps` (GPS device tracking), `cp-att` (attendance + payroll), `cp-exp` (expenses), `cp-fr` (freight rates + trader/vehicle masters), `cp-profile` (profile + account management/permissions/registration approvals).

## 2. Inline `<style>` Blocks (~30)

Multiple sequentially-added "final fix" / "override" style blocks (dark/light theme via `html[data-theme]`, responsive breakpoints, per-module styling). Source order = cascade order, so straight extraction into separate files in document order preserves the exact rendered result.

## 3. Inline `<script>` Blocks (17, ~4,700 lines)

Core app (seed data + all CRUD/render logic for every module), account-management/auth store (`srt_login_accounts_v1`, `SRT_MODULES`/`SRT_MODULE_SECTIONS` permission matrix), registration workflow, gallery admin, home-page interactions, motion/animation, notifications/chat, print/export helpers, Google-Sheets sync webhook, login-page UX, demo-data importer, generic CSV/XLSX transfer, and the entire embedded Tax-Invoice/Payment-Voucher sub-app (with its own Tailwind CDN + inline jsPDF).

## 4. Embedded Data (→ became DB tables)

Hardcoded JS arrays: `INIT_INV` (141 rows), `INIT_PAY` (137), `INIT_CP` (101), `INIT_RP` (0), `INIT_GPS` (16, mostly `"-"` placeholders except vehicle/GPS-id/owner/mobile), `INIT_ATT`, `INIT_EXP` (14), `INIT_FR` (96 city rates), `MONTHLY` payroll, precomputed `KPI` dashboard counters, plus detailed `ATT`/`GPSD` state objects. All harvested via a Node VM sandbox (`scripts/extract_seed_data.js`) into `db/seed/*.json` for faithful migration seeding.

## 5. Embedded SQL

None — all "querying" was JS `.filter()`/`.sort()` over in-memory arrays; replaced with real SQLAlchemy queries.

## 6. Media

9 embedded base64 PNGs, de-duplicated to **3 unique images** (~355KB decoded) via SHA1 content hashing, decoded to real files under `app/static/media/`.

## 7. Forms, Buttons, Implied API Endpoints

Only one real `<form>` (`#srt-login-form`); everything else is a modal driven by 217 inline `onclick=` handlers calling global JS functions. Implied API surface: auth/login, registration-request/approve/reject, per-module CRUD, users/permissions, GPS, attendance (staff/records/holidays/salary), dashboard KPIs.

## 8. Broken / Duplicated / Insecure Findings

1. **No real backend** — the entire premise of this rebuild.
2. **Plaintext-style credential storage** in `localStorage` — replaced with server-side bcrypt hashing + JWT.
3. **Client-exposed Google Sheets webhook URL** — left as-is (out of migration scope this iteration, documented as a known limitation).
4. **Duplicated/overridden CSS** across many "final fix" blocks — preserved via source-order extraction (cascade-safe), not a bug.
5. **Tailwind CDN leakage** inside the isolated Tax-Invoice sub-app — preserved as-is, doesn't conflict with the main app.
6. **Embedded minified library source** (jsPDF) inline as a JS string — extracted into a standalone static HTML file.
7. **217 inline `onclick` handlers** — preserved for fidelity; called out for future refactor.
8. **"Stale admin credential" safeguard** in `srtLoadAccounts()` (05-srt-account-management-script.js): silently wipes the active session for any account with `id==='admin'` whose `credentialRevision` doesn't match a hardcoded constant. This is a *legitimate* legacy safeguard, but it silently broke the new server-backed admin login until specifically discovered and accounted for during E2E browser testing (see Final Report).

## 9. Visual Baseline

The decomposed shell (`app/templates/legacy_full.html`) is generated by `scripts/decompose.py` directly from `original.html`, preserving exact DOM structure, cascade order, and behavior; verified via automated broken-static-link checks (`tests/test_pages.py`) and full-browser E2E tests (`scripts/e2e_*_test.py`).
